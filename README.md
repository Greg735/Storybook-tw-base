# storybook-tw-base

A **Storybook 10** workspace for building and documenting UI components with **Twig** templates and **Tailwind CSS 4**, designed to be reused in a Drupal theme. It is the Tailwind version of storybook-base: same components, same Twig variables, same design.

It is also a **versioned package**: a project installs it, gets every component and overrides only what it needs (see [Start a new project](#start-a-new-project) and [Use in a project](#use-in-a-project)).

- **Storybook** `@storybook/html-vite` (HTML + Vite)
- **Twig** compiled by `vite-plugin-twig-drupal` (its `drupal-twig-extensions` import is satisfied by a minimal local module, `packages/drupal-twig-extensions`, which only registers `attach_library()` as a no-op)
- **Tailwind CSS 4** + **Bootstrap Icons** (icon font only: there is no Bootstrap CSS or JS)
- **Vite** for assets (`config/assets.mjs`): Tailwind (`@tailwindcss/postcss`, then `optimize()` from `@tailwindcss/node`) and JS (concatenation + `terser`)
- **Vanilla Drupal behaviors** for the interactive components (accordion, alert, carousel, modal, tooltips…), one Drupal library each
- **Vitest** + Playwright for story tests (`@storybook/addon-vitest`)

## Requirements

- [DDEV](https://ddev.com/) (recommended), or
- Node.js **22** (see `.nvmrc`) if you run the commands outside DDEV

## Installation

```bash
git clone git@github.com:Greg735/storybook-tw-base.git
cd storybook-tw-base
ddev start
ddev npm install
```

DDEV installs the Playwright Chromium browser on start (needed for `npm test`).

## Development

| Command | Description |
| --- | --- |
| `ddev npm run develop` | Assets (build + watch) and Storybook together |
| `ddev npm run storybook` | Storybook only, on port `6006` in the container |
| `ddev npm run assets` | Build assets once |
| `ddev npm run assets:watch` | Build assets, then rebuild on changes |
| `ddev npm run build-storybook` | Static build into `storybook-static/` |
| `ddev npm test` | Run story tests with Vitest (headless Chromium) |
| `ddev npm run test:watch` | Vitest in watch mode |
| `ddev npm run lint` | ESLint, then Prettier check |
| `ddev npm run format` | Format the sources with Prettier |

After a Playwright upgrade, run `ddev restart` (or `ddev npx playwright install chromium`) to download the matching browser.

CI (`.github/workflows/ci.yml`) runs `lint`, `assets` (and fails if `dist/` or `public/` differ from a fresh build), `test` and `build-storybook`. Dependabot keeps npm packages and GitHub Actions up to date.

Without DDEV, drop the `ddev` prefix (`npm run develop`, …).

With DDEV, Storybook is available at **https://storybook-tw-base.ddev.site:6008** (DDEV routes container port 6006 to 6008, so it can run next to storybook-base).

> Storybook loads `/css/style.css` and `/js/sb-main.js` from `public/`, which are generated by the assets build. If styles or JS behaviors are missing, run `ddev npm run assets` (or use `develop`).

## How it works

### Styles

- `stories/core.css`: Tailwind's theme and utilities (no preflight), the foundations and the component utilities. Everything in it is free when unused (tokens and base styles aside): utilities are only output when a scanned source uses them. Automatic source detection is off (`source(none)`): the classes are found where the build says (see below).
- `<name>.deps.css` (listed by `stories/components/deps.css` and `stories/utilities/deps.css`): what a component pulls in only when it is used: its vendor CSS (Leaflet, GLightbox, Bootstrap Icons, scrollCue) and the classes picked by Twig variables (`@source inline(…)`).
- `stories/tailwind.css`: the whole design system, `core.css` plus every `deps.css` (Storybook, or a theme that wants everything).
- `stories/foundations/theme.css`: the design tokens (`@theme`): colors (`primary`…`dark`, `blue`…`teal`, `gray-100`…`gray-900`, `-subtle`, `-border-subtle`, `-emphasis`), `--contrast-*` (readable text color on each background), breakpoints (`sm` 576px … `xxl` 1400px), container widths, heading and display sizes (`text-h1`…`text-h6`, `text-display-1`…`6`), radii, shadows. Same values as the former Bootstrap configuration; Tailwind's default palette, radii, shadows and font sizes are reset.
- `stories/foundations/base.css`: element defaults, the equivalent of Bootstrap's reboot (headings, paragraphs, lists, links, forms…), so that plain HTML from Drupal or CKEditor keeps the same look.
- `stories/foundations/utilities.css` and the component CSS files: custom Tailwind utilities (`@utility`), used like any other class and only output when used: `container`, `text-bg-*`, `bg-gradient`, `btn-close`, `visually-hidden`, `btn` + `btn-*` / `btn-outline-*` / `btn-sm` / `btn-lg`, `badge`, `link-*`, `form-control`, `form-select`, `form-check`, `form-check-input`, `form-switch`, `form-floating`, `form-range`…
- The Twig templates use Tailwind utilities. Classes built from a variable (`'btn-' ~ type`, `text-display-{{ level }}`) are listed with `@source inline(…)` in the component CSS, so they exist even though Tailwind cannot see them in the template.

Spacing follows Tailwind's scale: Bootstrap's `*-1`, `*-2`, `*-3`, `*-4`, `*-5` are `*-1`, `*-2`, `*-4`, `*-6`, `*-12`. Bootstrap rows and columns are written as a wrapping flex row with percentage widths: `-mx-3 flex flex-wrap *:max-w-full *:shrink-0 *:px-3` on the row, `w-full md:w-1/2` on the columns. Do not use `grid grid-cols-12` with a gap instead: 12 columns and 11 gaps overflow on small screens, and Masonry needs percentage widths.

### Assets build

`config/assets.mjs` (`defineAssetsConfig()`, run by `npm run assets` / `assets:watch`):

1. cleans `dist/`
2. copies Bootstrap Icons fonts and custom fonts
3. compiles `stories/main.css` with Tailwind, scanning the `stories/` folder of every layer → `public/css/style.css` and `dist/css/style.css` / `style.min.css`
4. writes the CSS sources to `dist/css/src/` (vendor CSS copied to `dist/css/src/vendor/`) and the Tailwind entry of the Drupal theme, `dist/css/tailwind.css`, which scans `dist/components/`
5. bundles vendor JS (Leaflet, scrollCue, GLightbox, Masonry) and all `*.behaviors.js` → `public/js/sb-main.js` and `dist/js/` (+ `.min.js`), and writes one file per behavior (`dist/js/components/`), per vendor (`dist/js/vendor/`) and the Drupal libraries (`dist/libraries.yml`)
6. copies component Twig templates to `dist/components/` (relative includes rewritten to `@components/…`, library namespace set to the theme's)
7. copies images from `public/img/` to `dist/img/`
8. in watch mode, rebuilds only what changed: `*.css` → styles; `*.twig` (not `*.local.twig`) → Twig copy and styles; `*.behaviors.js` → JS and styles; other `*.twig`, `*.js` and `*.md` → styles (classes live in the templates and stories)

### Twig templates

- `*.twig` → distributable component templates, copied to `dist/components/`
- `*.local.twig` → story/demo examples only, **not** copied to `dist/`

### JavaScript behaviors

Component JS lives in `*.behaviors.js` files and uses `Drupal.behaviors` + `once()` (never `DOMContentLoaded`). There is no Bootstrap JS: accordion, dismissible alert, carousel, modal (native `<dialog>`, opened by `data-modal-target="#id"`) and tooltips (`data-tooltip="…"`, the former `data-bs-toggle="tooltip"` + `data-bs-title` still work) are small vanilla behaviors. In Storybook, `config/preview-head.html` provides a minimal `Drupal` / `once()` shim so behaviors run as they would in Drupal.

A behavior declares the Drupal libraries it needs in its header (vendor libraries of this build without a slash, others in full):

```js
/**
 * @file Leaflet map with a marker (and its popup).
 *
 * @drupal-dependencies leaflet
 */
```

### Drupal integration

- **Templates**: `dist/components/`, included with `@components/…` (Components module namespace).
- **Reference theme**: drusttw4 (Drupal 11), which syncs `dist/`, compiles its CSS from the components it includes and generates its libraries file.
- **CSS**: compiled by the Drupal theme, from the sources in `dist/` (only `tailwindcss` needs to be installed):

  ```css
  @import '../dist/css/tailwind.css';
  @source '../templates';
  ```

  `dist/css/tailwind.css` scans all of `dist/components/` and imports every component dependency; add the theme templates with `@source`. To compile only the components the theme uses, import `dist/css/src/core.css` instead, with an `@source` and the `<name>.deps.css` of each component its templates include: the [drusttw4](https://github.com/Greg735/drusttw4) theme does it automatically (`scripts/build-css.mjs` follows the `@components/…` includes). Font URLs are relative to `dist/css/`: write the compiled CSS there, or copy `dist/css/fonts/` next to it. The compiled `dist/css/style.css` / `style.min.css` remain available if the theme does not compile its CSS.
- **JS**: one Drupal library per behavior. Copy `dist/libraries.yml` into `<theme>.libraries.yml`: it lists `vendor-<name>` libraries (`dist/js/vendor/`) and one library per behavior (`dist/js/components/<name>.js`, depending on `core/drupal`, `core/once` and its vendors). Components with JS attach theirs, e.g. `{{ attach_library('storybook_tw_base/accordion') }}`; in `dist/components/`, `storybook_tw_base` is replaced by the `library` option of the project (see [Start a new project](#start-a-new-project)). The utilities libraries (`tooltips`, `masonry`, `animations`) are attached by the theme where it needs them (the carousel attaches `image-lightbox` and `animations` itself). `dist/js/sb-main.js` still bundles everything, for a theme that loads all the JS at once.

## File structure

```
├── .ddev/                  # DDEV configuration
├── .storybook/             # Storybook configuration (main, preview, manager theme)
├── stories/                # Source files
│   ├── tailwind.css        # Design system entry (imported by projects)
│   ├── main.css            # Storybook entry of this repository
│   ├── assets/             # Static assets served at /assets
│   ├── documentation/      # Documentation stories (introduction…)
│   ├── foundations/        # Tokens, base styles, utilities; colors, typography, headings, forms…
│   ├── utilities/          # Shared helpers: animations, icons, masonry, tooltips
│   └── components/         # Reusable UI components
├── public/                 # Generated assets served by Storybook (do not edit css/ and js/)
├── dist/                   # Generated distributable output: css (+ sources), js, components, img, libraries.yml (do not edit)
├── storybook-static/       # Generated static Storybook (ignored)
├── config/                 # Shared Storybook + assets config (also used by projects)
├── packages/               # Local drupal-twig-extensions (attach_library no-op)
├── vite.assets.config.mjs  # Assets build entry (calls config/assets.mjs)
├── vitest.config.js        # Vitest / story tests
└── package.json
```

## Adding a component

Create a folder `stories/components/<name>/` with only the files you need:

```
<name>.twig            # Template (distributed), with Tailwind utility classes
<name>.css             # Custom utilities, safelisted classes, vendor CSS (optional)
<name>.stories.js      # Stories
<name>.docs.md         # Documentation (optional)
<name>.behaviors.js    # Behavior using Drupal.behaviors + once() (optional)
```

If the component has a CSS file, register it in `stories/components/index.css` (one line per component):

```css
@import './<name>/<name>.css';
```

If it has a behavior, attach its library at the top of the template:

```twig
{{ attach_library('storybook_tw_base/<name>') }}
```

Stories follow this pattern:

```js
import template from './example.twig';
import source from './example.twig?raw';

export default {
  title: 'Components/Example',
  parameters: {
    componentSource: { code: source, language: 'twig' },
  },
};

const Template = (args) => template(args);

export const Default = Template.bind({});
Default.args = { /* … */ };
```

## Generated files

Do not edit `public/css/`, `public/js/`, `dist/` or `storybook-static/` by hand: change the sources in `stories/` (or `config/` / `.storybook/`) and rebuild. Note that `dist/` is versioned, so check `git status` after a build.

## Start a new project

A new design system project (e.g. for a Drupal sub-theme) installs storybook-tw-base as a dependency and only keeps its own files: tokens, overrides and project components.

Summary:

1. create the repository and DDEV
2. write `package.json` (storybook-tw-base tag, excludes, library namespace)
3. add the Storybook, assets and test config files
4. add the CSS entry point
5. install, build and run
6. customize (tokens, overrides, new components)
7. document and commit

### 1. Create the repository and DDEV

```bash
mkdir my-project && cd my-project
git init
mkdir -p .ddev .storybook stories/components public/img
cp ../storybook-tw-base/.ddev/config.yaml .ddev/
cp ../storybook-tw-base/.nvmrc ../storybook-tw-base/.gitignore .
cp ../storybook-tw-base/.storybook/manager.js ../storybook-tw-base/.storybook/MyTheme.js .storybook/
cp ../storybook-tw-base/vitest.config.js .
```

In `.ddev/config.yaml`, set `name: my-project` (the Storybook URL becomes `https://my-project.ddev.site:6008`). Keep `nodejs_version`, `web_extra_exposed_ports`, the `post-start` hook and `webimage_extra_packages`: they provide Node 22, the Storybook port and Playwright Chromium for the tests. DDEV routes by host name, so several projects can use the same ports.

Optional: `public/favicons/` (copied to `dist/favicons/`) and `public/img/` for project images, such as the logo.

### 2. `package.json`

```json
{
  "name": "my-project",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "scripts": {
    "assets": "vite build --config vite.assets.config.mjs",
    "assets:watch": "vite build --config vite.assets.config.mjs --watch",
    "storybook": "storybook dev --no-open -p 6006 --host 0.0.0.0",
    "develop": "concurrently --raw --kill-others \"npm run assets:watch\" \"npm run storybook\"",
    "build-storybook": "storybook build",
    "test": "vitest run",
    "test:watch": "vitest"
  },
  "dependencies": {
    "storybook-tw-base": "github:Greg735/storybook-tw-base#vX.Y.Z"
  },
  "devDependencies": {
    "@storybook/addon-a11y": "^10.6.2",
    "@storybook/addon-docs": "^10.6.2",
    "@storybook/addon-links": "^10.6.2",
    "@storybook/addon-vitest": "^10.6.2",
    "@storybook/html-vite": "^10.6.2",
    "@tailwindcss/node": "^4.1.0",
    "@tailwindcss/postcss": "^4.1.0",
    "@vitest/browser-playwright": "^5.0.5",
    "@vitest/coverage-v8": "^5.0.5",
    "concurrently": "^10.0.6",
    "playwright": "^1.64.1",
    "postcss": "^8.5.28",
    "storybook": "^10.6.2",
    "tailwindcss": "^4.1.0",
    "terser": "^5.31.1",
    "tinyglobby": "^0.2.17",
    "twig": "^3.0.0",
    "vite": "^8.3.4",
    "vite-plugin-twig-drupal": "^1.7.0",
    "vitest": "^5.0.5"
  },
  "overrides": {
    "drupal-twig-extensions": "$storybook-tw-base"
  },
  "storybook-tw-base": {
    "exclude": [],
    "library": "my_theme"
  }
}
```

- `#vX.Y.Z`: the storybook-tw-base tag to use, exactly the tag name (the latest one: `git tag` here)
- `overrides`: replaces the vulnerable `drupal-twig-extensions` npm package by the one storybook-tw-base provides. Keep it as is
- `storybook-tw-base.exclude`: base components the project does not use (see [Excluding components](#excluding-components)). Can stay empty
- `storybook-tw-base.library`: the machine name of the Drupal theme, used in the `attach_library()` calls of `dist/components/` and in `dist/libraries.yml` (default `storybook_tw_base`)
- the `devDependencies` are the toolchain of this repository: keep their versions in line with its `package.json`

### 3. Config files

`.storybook/main.js` (use the DDEV host of the project):

```js
import { defineStorybookConfig } from 'storybook-tw-base/storybook';

/** @type { import('@storybook/html-vite').StorybookConfig } */
export default defineStorybookConfig({
  hosts: ['my-project.ddev.site'],
});
```

`.storybook/preview.js` (`storySort` and `tags` must stay written here: Storybook reads them statically and does not follow imports; without `tags: ['autodocs']`, the Docs pages are missing):

```js
import preview from 'storybook-tw-base/preview';

// storySort and tags are kept here as literals: Storybook reads them
// statically from this file, without following imports.
/** @type { import('@storybook/html-vite').Preview } */
export default {
  ...preview,
  parameters: {
    ...preview.parameters,
    options: {
      storySort: {
        // Sub-menus in alphabetical order.
        method: 'alphabetical',
        order: ['Documentation', 'Foundations', ['headings', '*'], 'Utilities', 'Components', 'Pages', '*'],
      },
    },
  },
  tags: ['autodocs'],
};
```

`vite.assets.config.mjs`:

```js
import { defineAssetsConfig } from 'storybook-tw-base/assets';

export default defineAssetsConfig();
```

`.storybook/manager.js` (copied in step 1): add the storybook-tw-base sidebar, which marks the storybook-tw-base components with an icon (see [Use in a project](#use-in-a-project)):

```js
import { addons } from 'storybook/manager-api';
import { sidebar } from 'storybook-tw-base/manager';
import MyTheme from './MyTheme';

addons.setConfig({
  theme: MyTheme,
  sidebar,
});
```

`vitest.config.js`: the copy of this repository's, as is (step 1).

`.storybook/MyTheme.js`: the project branding (`brandTitle`, `brandUrl`, `brandImage`). A logo in `public/img/` is imported with `import logo from '../public/img/logo.png';`.

### 4. CSS entry point

The project CSS is split like storybook-tw-base's, so that a Drupal theme can compile only the components it uses (see [drusttw4](https://github.com/Greg735/drusttw4)).

`stories/core.css`: what costs nothing when unused (tokens, base styles, component utilities):

```css
/* storybook-tw-base core (Tailwind without preflight, tokens, base, components). */
@import 'storybook-tw-base/stories/core.css';

/* Token overrides. */
@theme {
  --color-primary: #c8102e;
  --contrast-primary: #fff;
}

/* Project components, and the storybook-tw-base component styles it replaces. */
@import './components/index.css';
```

`stories/main.css` (Storybook entry):

```css
@import './core.css';
/* Dependencies (vendor CSS, safelists) of the storybook-tw-base components. */
@import 'storybook-tw-base/stories/deps.css';
/* Dependencies of the project components, if any. */
@import './components/deps.css';
```

Import storybook-tw-base files with the `storybook-tw-base/stories/…` path: the assets build recognizes it to apply `exclude` and the replaced component styles, and rewrites it in the sources copied to `dist/css/src/`. Do not add `@source` lines: the build scans the `stories/` folder of the project and of storybook-tw-base, and `dist/css/tailwind.css` scans `dist/components/`.

`stories/components/index.css` (empty to start with): one line per project component with a CSS file, and per storybook-tw-base component whose CSS the project replaces:

```css
@import './hero/hero.css';
```

`stories/components/deps.css` (empty to start with): one line per project component with dependencies (`<name>.deps.css`: vendor CSS, classes picked by Twig variables), or per storybook-tw-base `<name>.deps.css` the project replaces.

### 5. Install and run

DDEV installs storybook-tw-base from GitHub over SSH, so the container needs your SSH key (again after each `ddev poweroff` or reboot):

```bash
ddev start
ddev auth ssh
ddev npm install
ddev restart             # first time only: the post-start hook installs Playwright Chromium for the tests
ddev npm run assets
ddev npm test
ddev npm run develop     # https://my-project.ddev.site:6008
```

The Storybook shows every storybook-tw-base story (including *Documentation / Introduction*), except the excluded and replaced ones, plus the project stories.

### 6. Customize

See [Use in a project](#use-in-a-project) for where each change goes. In short, a project file at the same path as a storybook-tw-base file replaces it, and only that file:

- **tokens** (colors, fonts, sizes): an `@theme` block in `stories/core.css`, after the storybook-tw-base import
- **component styles**: `stories/components/<name>/<name>.css`, imported in `stories/components/index.css`
- **template**: `stories/components/<name>/<name>.twig`
- **story or docs**: `stories/components/<name>/<name>.stories.js`, importing the template with `@components/<name>/<name>.twig` (it resolves to the project template if there is one, else to the storybook-tw-base one). A relative import such as `./<name>.docs.md?raw` needs the file in the project too: use `@components/<name>/<name>.docs.md?raw` to keep the base docs
- **behavior**: `stories/components/<name>/<name>.behaviors.js`
- **new component**: `stories/components/<name>/`, as described in [Adding a component](#adding-a-component); its Twig includes use `@components/…`, its `attach_library()` calls the `storybook_tw_base/` namespace (rewritten in `dist/`)
- **pages**: `stories/pages/` (title `Pages/…`)

After changing `package.json` (excludes, library) or adding a story file, restart Storybook; after a CSS, template, behavior or story change, `ddev npm run develop` rebuilds the assets.

### 7. Document and commit

- Write a project `README.md` (what the project adds, overrides and excludes) and an `AGENTS.md` for the agents
- Commit the project, including `dist/` (used by the Drupal theme) and `public/css/`, `public/js/`. `node_modules/` and `storybook-static/` are ignored by the copied `.gitignore`
- Add its GitHub remote and push

### Developing storybook-tw-base and a project together

To try unreleased storybook-tw-base changes in a project, point the dependency to the local folder instead of a tag:

1. `"storybook-tw-base": "file:../storybook-tw-base"` in the project `package.json`
2. mount the folder in the DDEV web container, with `.ddev/docker-compose.storybook-tw-base.yaml`:

   ```yaml
   services:
     web:
       volumes:
         - ../../storybook-tw-base:/var/www/storybook-tw-base:ro
   ```

3. `ddev restart`, then copy the current storybook-tw-base files into `node_modules/` (again after each change):

   ```bash
   ddev exec "rm -rf node_modules/storybook-tw-base && npm install --install-links ../storybook-tw-base"
   ```

Go back to a `github:…#vX.Y.Z` dependency (and remove the mount) before committing the project.

## Use in a project

What a project gets from storybook-tw-base, and how it overrides it:

| To… | In the project |
| --- | --- |
| change colors, fonts, spacing | redefine the tokens of `stories/foundations/theme.css` in an `@theme` block of `stories/core.css`, after the storybook-tw-base import (a color usually comes with its `--contrast-*` token) |
| replace a component's styles | add `stories/components/<name>/<name>.css` (only that file) and import it in `stories/components/index.css`: the storybook-tw-base `<name>.css` is then left out. To extend it instead, start your file with `@import 'storybook-tw-base/stories/components/<name>/<name>.css';` |
| replace a component's template | add `stories/components/<name>/<name>.twig`: it wins everywhere (`@components/…` includes, base stories, `dist/`) |
| replace a behavior or a story | add the `*.behaviors.js` or `*.stories.js` at the same path (a replaced base story is hidden). A story alone works: it imports the template with `@components/…`, which resolves to the storybook-tw-base one. Keep the same file path and title, else both stories are listed |
| add a component | add `stories/components/<name>/` as usual, importing templates through `@components/…` |
| remove a component | list it in `package.json` → `storybook-tw-base.exclude` (see below) |

In the project's Storybook, the sidebar (`sidebar` from `storybook-tw-base/manager`) shows where each component comes from:

| Icon | Origin | Tag |
| --- | --- | --- |
| box (grey) | storybook-tw-base, used as is | `storybook-tw-base` |
| pencil (orange) | storybook-tw-base story, but the project overrides files of its folder (`*.twig` except `*.local.twig`, `*.css`, `*.behaviors.js`) | `storybook-tw-base-overridden` |
| none | the project | – |

The tags are added when the stories are indexed (`experimental_indexers` in `config/storybook.js`), so the sidebar tag filter can also show or hide each origin. Nothing is hidden by default.

Importing `storybook-tw-base/manager` also hides the addon panel on the stories tagged `no-panel` (such as *Documentation / Introduction*) and shows it again on the others.

### Excluding components

Base components the project does not use are listed in its `package.json`:

```json
"storybook-tw-base": { "exclude": ["modal", "map"] }
```

Entries are component names (`stories/components/<name>/`) or paths relative to `stories/` (`utilities/tooltips`). An excluded component is left out of Storybook, `dist/components/` (so the Drupal theme's Tailwind does not see its classes), the component styles, `sb-main.js` and `dist/libraries.yml`. After changing the list, run `ddev npm run assets` and restart Storybook. The assets build warns when a kept template includes an excluded one, as Drupal would not find it.

### Updating storybook-tw-base in a project

1. **Release storybook-tw-base** (here), after committing the changes:

   ```bash
   ddev npm version patch   # or minor / major: sets "version" in package.json, commits and tags vX.Y.Z
   git push --follow-tags
   ```

2. **In the project**, install the new tag, then align the second copy of storybook-tw-base:

   ```bash
   ddev auth ssh            # once per DDEV start: npm fetches the tag over SSH
   ddev npm install storybook-tw-base@github:Greg735/storybook-tw-base#vX.Y.Z
   ddev npm update drupal-twig-extensions
   ddev npm run assets
   ```

   Then restart Storybook (`ddev npm run develop`): it reads the stories and the storybook-tw-base config at start only. In the Drupal theme, recompile the CSS and check `dist/libraries.yml` for new libraries.

3. **Check** `package-lock.json`: `node_modules/storybook-tw-base` and `node_modules/drupal-twig-extensions` must have the same `resolved` commit, the one of the new tag. Their `version` is the `"version"` field of storybook-tw-base's `package.json`, not the tag: `npm version` keeps both aligned.

4. Overridden files are not updated: compare them with the new base version.

Why these commands:

- `npm install storybook-tw-base@github:…#vX.Y.Z` rather than editing the tag in `package.json` and running `npm install`: with git dependencies, npm does not always resolve the new tag and keeps the commit of the lockfile.
- `drupal-twig-extensions` is a **second copy of storybook-tw-base**, installed by `"overrides": { "drupal-twig-extensions": "$storybook-tw-base" }` (it replaces the vulnerable npm package that `vite-plugin-twig-drupal` depends on). npm keeps its lockfile entry on the previous commit until it is updated. The project only uses its `twig.js` (`packages/drupal-twig-extensions/`, which registers `attach_library()` as a no-op): the update only matters when that file changed, but run it every time so both copies stay on the same commit. If its `resolved` commit still does not change, remove `node_modules/drupal-twig-extensions` and its block in `package-lock.json`, then run `ddev npm install`.
